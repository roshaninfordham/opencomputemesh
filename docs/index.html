Install in three steps

Two downloads and a browser tab. Hosting a network takes Python; contributing compute takes one binary and Ollama; sending prompts takes nothing.

1. Host a network

One machine, Python 3.12+ and uv. The wheel does not contain the web app, so unzip the bundle where the coordinator serves it from.

curl -LO .../opencomputemesh-0.1.1-py3-none-any.whl
curl -LO .../opencomputemesh-web-0.1.1.zip
unzip opencomputemesh-web-0.1.1.zip -d web/dist
uv tool install ./opencomputemesh-0.1.1-py3-none-any.whl
OCM_WEB_DIST=./web/dist ocm serve

Prints Join path: /join/<code>. Binds 127.0.0.1:8000 unless you set OCM_HOST.

2. Share your models

Install Ollama, pull a model, and create an enrollment token in the web app under Nodes. Then run the binary for your OS. It dials out and opens no ports.

# macOS, Apple silicon (unsigned: clear quarantine)
chmod +x ocm-node-0.1.1-aarch64-apple-darwin
xattr -d com.apple.quarantine ocm-node-0.1.1-aarch64-apple-darwin
ollama pull qwen2.5:1.5b
./ocm-node-0.1.1-aarch64-apple-darwin \
  --coordinator https://your-coordinator \
  --models qwen2.5:1.5b --name my-laptop

Linux uses the musl binary, Windows the .exe, with the same flags.

3. Join from any device

Open /join/<code> on a phone, tablet or laptop and pick a nickname.

  1. No install, no account.
  2. Joining shares no compute.
  3. Capacity exists only while someone runs an agent with approved models.

Verify a host with curl /healthz and ocm check-ledger.

What it does

Routes to hardware it does not own

One coordinator picks an online node that actually serves the exact model, places a worst-case credit hold, and streams tokens back over that node's outbound socket.

Receipts with provenance

Token counts and timings come from the runtime, the coordinator or the browser, and say which. When a value was not reported it stays empty instead of being estimated.

An append-only ledger

Non-cash credits move per job, charges are capped at the hold the requester agreed to, and ocm check-ledger proves every job's debit and reward cancel out.

Two agents, one contract

Python ocm-agent and Rust ocm-node share flags, environment variables and state file. The Rust one is a single binary for macOS, Windows and Linux.

Optional tiers, honest labels

Ollama on loopback by default; an opted-in remote runtime or the Gemini API when the owner says so. Only the Tinfoil enclave can be attested, so contributor nodes are labelled attested: false.

No prompt storage

Prompts live in coordinator memory for the length of a job. They are never written to the database or logs, and the Sentry scrubbers drop bodies, cookies and tokens before anything leaves the machine.

Built with our sponsors

Gemini API

A second runtime adapter beside local Ollama: a node owner runs ocm-agent --runtime gemini and shares Gemini models. Gemini's usageMetadata becomes the token counts on that node's receipts; the API key stays on the node.

Unit-tested against the documented API format. Not run live: no API key was available.

Tiger Data

When OCM_TIMESCALE_URL is set, every finished job's metrics (never prompts) go to a TimescaleDB hypertable. A continuous aggregate with real-time aggregation drives the Throughput chart.

Verified live against a local TimescaleDB 2.30.2. Not yet run on Tiger Cloud.

Sentry

Opt-in error monitoring for the coordinator (SENTRY_DSN), with scrubbers that strip prompts, request bodies, cookies, tokens and join codes before anything is sent.

Tested through the real SDK with an in-memory transport. Not sent to a live project: no DSN was available.
