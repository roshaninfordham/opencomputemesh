# OpenComputeMesh v0.2.5: edge configuration and sharing

Status: approved for implementation, 2026-11-07.
License: Apache-2.0 (unchanged).
Inspiration: [nginx](https://github.com/nginx/nginx) — one declarative file, a test
mode, a reload signal, upstream pools and route matching.

## 1. Intent

A person should be able to publish compute, point their own AI agents at it, and
run free open source models — without learning a dozen environment variables or
hand-assembling flags. Everything about how the edge behaves is described in one
readable file, checked before it is applied, and applied without dropping work.

Three outcomes define success:

1. **One URL shares compute.** A share link is generated from config, sent to a
   person, and opening it tells them exactly how to contribute.
2. **Any agent can use it.** A named key with a model allowlist, a credit budget
   and a rate limit is configurable, and every OpenAI-compatible client works.
3. **Free models, self-served.** A model can be pulled, digest-pinned and served
   by the person running the network, with no paid dependency.

## 2. What we take from nginx, and why

| nginx | OpenComputeMesh | Why it earns its place |
|---|---|---|
| `nginx.conf` | `ocm.conf` | One file that describes the whole edge; reviewable in a diff |
| `http`/`server`/`location` contexts | `network` / `route` / `pool` | Familiar nesting; no invented vocabulary |
| `upstream` block | `pool` block | A pool *is* the set of workers for one model digest |
| `auth_basic`, `limit_req` | `token` block | Key, allowlist, budget and rate in one place |
| `include conf.d/*.conf` | `include` | Split config per site without a new mechanism |
| `nginx -t` | `ocm -t` | Fail before you serve; report everything, not the first error |
| `nginx -s reload` | `ocm reload` | Change routing policy without dropping streams |
| `worker_processes` | generated by the coordinator | No tuning knob we cannot justify |

Deliberately **not** borrowed: dynamic module loading, `if` blocks, regex rewrite
chains, embedded scripting. Each one turns configuration into a programming
language with its own bugs. Out of scope in §10.

## 3. The configuration language

Grammar:

```text
document   := directive*
directive  := WORD arg* ( ';' | '{' directive* '}' )
arg        := WORD
```

Lexing rules:

- `#` starts a comment that runs to end of line.
- Whitespace separates arguments; newlines carry no meaning.
- `"..."` is one argument; `\"` `\\` `\n` `\t` are escapes.
- Bare arguments end at whitespace, `{`, `}`, `;`, `#` or `"`.
- `{`, `}` and `;` are structural and cannot appear inside a bare argument.

Limits, enforced by the parser rather than discovered later: block nesting is
bounded ([`MAX_DEPTH`] = 32), a document with a missing `;` or `}` is rejected
rather than partially applied, and error text never contains file contents.

### Include

`include <path>;` is recognised at top level. In P0 it is parsed and retained but
not expanded, and it does not pretend otherwise. P1 adds glob expansion, cycle
detection and a depth limit, with errors reported against the *included* file's
own `file:line:column`.

## 4. Directive reference

### `network "<name>" { ... }`

Required, exactly one. The edge itself.

| Setting | Values | Default | Meaning |
|---|---|---|---|
| `listen` | port 1-65535 | `8080` | TCP port the coordinator binds |
| `data_dir` | path | `/var/lib/ocm` | Where the database and join code live |
| `demo_mode` | `on`/`off` | `on` | Grant demo credits on join |

### `token "<name>" { ... }`

A key an agent presents as `Authorization: Bearer ...`. Names are unique.

| Setting | Values | Default | Meaning |
|---|---|---|---|
| `allow_models` | one or more model ids | all models | Models this key may reach; omitting it allows all, while an empty directive is an error |
| `budget` | `<n> OCC` | unlimited | Total credits this key may spend |
| `rate` | `<n>/s`, `<n>/min`, `<n>/h` | none | Sliding-window request limit |

### `share "<name>" { ... }`

A shareable URL, served at `/share/<name>`. Names are unique.

| Setting | Values | Default | Meaning |
|---|---|---|---|
| `enroll` | `node` or `request` | `node` | Whether the visitor may offer compute |
| `expires` | `<n>ms`, `s`, `m`, `h`, `d` | never | Link lifetime |
| `grant` | `<n> OCC` | demo default | Credits granted on use |
| `max_nodes` | integer >= 1 | unlimited | Nodes one link may enroll; `0` is rejected rather than read as unlimited |

### `pool "<name>" { ... }`

The workers serving one exact model. `model` is required.

| Setting | Values | Default | Meaning |
|---|---|---|---|
| `model` | model id | required | Exact id every worker must serve |
| `policy` | `expected_ms`, `fewest_active` | `expected_ms` | Selection policy |

### `route "<name>" { ... }`

An HTTP surface bound to a pool. `pool` is required and must be defined.

| Setting | Values | Default | Meaning |
|---|---|---|---|
| `path` | prefix starting `/` | `/<name>` | URL prefix to serve |
| `pool` | defined pool name | required | Where requests go |
| `auth` | `token` or `none` | `token` | Whether a bearer key is required |

## 5. Sharing compute with one URL

```bash
ocm share --pool small --for 24h
# https://mesh.example/share/friends
```

Opening the link shows one copy-paste command, never a wiki:

```bash
ocm join https://mesh.example/share/friends
```

The page also states, in plain words, what the visitor is granting: which model,
that the node owner can see prompts, and when the link expires.

Rules: a share link is single-use per node, bounded by `max_nodes`, expires on
schedule, and can be revoked by removing the block and reloading. "Unlimited" is
expressed by omitting the directive, never by a zero: an accidental `0` cannot
silently remove the only cap on a public URL. A `request`
share never grants compute — it only lets someone send prompts.

## 6. Sharing to your own agents

Any OpenAI-compatible client works once a `token` block exists.

```bash
ocm token create agents          # prints the key once
curl https://mesh.example/v1/chat/completions \
  -H "Authorization: Bearer $OCM_API_KEY" \
  -d '{"model":"qwen2.5:1.5b","messages":[{"role":"user","content":"hi"}]}'
```

Enforcement is server-side and ordered so a rejected request costs nothing:
authenticate → model allowlist → rate limit → budget hold → route to pool. Usage
is attributed per key so `allow_models` and `budget` are auditable.

## 7. Free open source models

```bash
ocm models add llama3.2:3b
```

resolves the model against the local runtime catalog, pulls it, records the
resolved digest, and prints the `pool` directive to paste. It does **not** edit
`ocm.conf` unless `--write` is passed: configuration stays explicit and
reviewable, which is the whole point of the file.

`ocm models list` shows id, digest, size and whether a pool already serves it.
`ocm models rm` refuses while a pool references the model.

## 8. Reload semantics

`ocm reload` (or `SIGHUP`) parses and validates the file, then swaps in a new
*generation*. Following nginx: an invalid file is rejected and the running config
is left untouched, with a non-zero exit and the full error list.

- New jobs use the new generation.
- In-flight jobs finish on the generation they started with; their streams are
  never truncated by a reload.
- Receipts record the generation, so a receipt can still be explained after the
  file changed.
- Revoking a token or share takes effect immediately for *new* requests.

## 9. Security

- The config file may describe keys but never contains secret material: `token`
  blocks name keys whose values are generated and hashed in the database.
- Diagnostics carry `file:line:column` and a directive-level detail only, so an
  `ocm -t` error is safe to paste into an issue.
- Share links are hashed at rest, single-use, expiring and revocable.
- Agent keys are shown once, stored hashed, and cannot exceed their allowlist,
  rate or budget.
- An allowlist that fails to parse is an error, never an implicit allow-all, so a
  typo cannot widen access.
- Reload never widens access: a config that fails validation changes nothing.

## 10. Out of scope

- `if` blocks, regex rewrites, embedded scripting (nginx's own footguns).
- Dynamic module loading.
- Inheritance between blocks (each block states its own values; v0.3 may revisit).
- Multi-file includes until P1.
- TLS termination, which stays the job of the tunnel or reverse proxy in front.

## 11. Acceptance criteria

1. `ocm -t` accepts `examples/ocm.conf` and exits 0.
2. `ocm -t` on an invalid file lists **every** problem with
   `file:line:column` and exits non-zero.
3. Unknown directives are rejected at top level and inside known blocks.
4. A duplicate `pool`, `token`, `share`, `route` or `network` name is rejected.
5. A `route` referencing an undefined `pool` is rejected, reported at the
   route's own file and position rather than at the top of the file.
6. Malformed durations, rates, ports, booleans and enums are rejected with the
   directive named.
7. Block nesting beyond `MAX_DEPTH` is rejected without a stack overflow.
8. A reload with an invalid file leaves the running configuration untouched.
9. A share URL onboards a node end to end with one command.
10. An agent key cannot exceed its `allow_models`, `rate` or `budget`.
11. A working network is describable without `OCM_*` environment variables.

Criteria 1-7 are satisfied by the `ocm-config` crate in this change. Criteria
8-11 belong to P1-P6 and are tracked in the Plan 2 checklist.
