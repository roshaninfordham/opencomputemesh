# v0.2.5 Plan 2: Edge configuration and sharing

> **For agentic workers:** work task by task. Each task ends with a green gate and
> one commit. Do not start a task before its prerequisite is merged.

**Goal:** make one `ocm.conf` describe a whole edge — port, models, tokens, share
links and limits — checked by `ocm -t` and applied by `ocm reload`, so a person can
share compute with one URL, serve their own agents, and run free OSS models.

**Spec:** `docs/superpowers/specs/2026-11-07-edge-config-and-sharing.md`
**Roadmap:** `docs/ROADMAP.md` Phase 1.5.

## Global constraints

- Rust-only runtime (`docs/RUST-POLICY.md`): no Python, no Node server.
- `ocm-config` stays I/O-free and dependency-free; the coordinator owns the filesystem.
- Diagnostics are `file:line:column` plus directive-level detail, never file contents.
- `validate()` reports every problem, not the first one.
- Every new directive needs: parser case, validation rule, fixture, doc row.
- `ocm -t` must accept `examples/ocm.conf` at all times.
- Gate per task: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`.

## Task 1 — the configuration language (P0)

**Files:** `crates/ocm-config/{Cargo.toml,src/{lib,ast,error,lexer,parse,validate}.rs}`,
`crates/ocm-config/tests/{parse,validate}.rs`, `crates/ocm-config/tests/fixtures/ocm.conf`,
`examples/ocm.conf`, `Cargo.toml`, `CHANGELOG.md`, `docs/DEPENDENCIES.md`.

**Interfaces produced:** `ocm_config::{parse, validate, test_config, Document, Node, Config,
NetworkCfg, TokenCfg, ShareCfg, PoolCfg, RouteCfg, Policy, Rate, Enroll, ConfigError,
ErrorKind, MAX_DEPTH, DEFAULT_SOURCE}`.

- [x] Lexer: words, quoted strings with escapes, `{}`, `;`, `#` comments, positions.
- [x] Parser: nested blocks, depth limit, missing terminator and unclosed block errors.
- [x] Validation: `network`, `token`, `share`, `pool`, `route`; typed output with defaults.
- [x] Cross-references: unique names, `route.pool` must exist, one `network` only.
- [x] Value shapes: duration (`ms|s|m|h|d`), rate (`n/s|min|h`), `n OCC`, port, bool, enums.
- [x] `test_config()` = parse + validate, the `ocm -t` semantics.
- [x] Tests: 22 across parser and validation, including a full-report assertion.
- [x] `examples/ocm.conf` validates.

**Deliberately deferred:** `include` is parsed and retained but not expanded (Task 2).

## Task 2 — include resolution (P1)

**Files:** `crates/ocm-config/src/include.rs`, tests.

- [ ] `resolve(doc, loader) -> Result<Document, Vec<ConfigError>>` where
      `loader: FnMut(&str) -> Option<String>`; expansion is depth-first in place.
- [ ] Glob support for `conf.d/*.conf` with deterministic ordering.
- [ ] Cycle detection (`IncludeCycle`) and depth limit (`IncludeDepth`).
- [ ] Errors point at the included file's own `file:line:column`.
- [ ] Test: three-file tree expands in order; a cycle is reported once.

## Task 3 — share URLs (P2)

**Files:** `ocm-coord` routes, `ocm-ledger`, web page, tests.

- [ ] `POST /api/v1/shares/{name}` issues a single-use token for a configured `share`.
- [ ] `GET /share/{token}` renders onboarding: one command, model, expiry, privacy note.
- [ ] Enforce `expires`, `max_nodes`, `enroll=node|request`; revocation on reload.
- [ ] `ocm share --pool <p> --for <dur>` prints the URL and a QR code.
- [ ] Test: happy path, expired link, over-max link, request-only link cannot enroll.

## Task 4 — agent tokens (P3)

**Files:** `ocm-coord` auth middleware, `/v1` handlers, usage queries, tests.

- [ ] `ocm token create <name>` prints the key once; stored hashed.
- [ ] Enforcement order: authenticate → allowlist → rate → budget hold → route.
- [ ] Per-key usage endpoint and receipt attribution.
- [ ] Test: model outside allowlist → 403; rate exceeded → 429; budget → 402.

## Task 5 — free OSS models (P4)

**Files:** `ocm-models` (or `ocm-coord` module), CLI, tests with a fake runtime.

- [ ] `ocm models add <id>` resolves, pulls, pins the digest, prints the `pool` directive.
- [ ] `--write` applies the directive; default never edits config silently.
- [ ] `ocm models list`, `ocm models rm` (refuses while a pool references the model).
- [ ] Test: unresolvable id, digest mismatch, remove-while-referenced.

## Task 6 — hot reload (P5)

**Files:** `ocm-coord` lifecycle, `ocm` CLI, tests.

- [ ] `ocm reload` and `SIGHUP` parse + validate, then swap a config generation.
- [ ] Invalid file: exit non-zero, keep the old generation, report every error.
- [ ] In-flight jobs finish on their starting generation; receipts record it.
- [ ] Test: reload while a stream is active does not truncate it.

## Task 7 — config over env (P6)

**Files:** `ocm/config` loader, docs, `.env.example`, tests.

- [ ] `ocm.conf` becomes the primary source; `OCM_*` becomes explicit overrides.
- [ ] Report which values came from which source at startup.
- [ ] Docs: configuration table split into "declarative" and "override" columns.
- [ ] Test: override wins; unknown override is rejected by name.

## Definition of done for Plan 2

- All seven tasks merged, each with its gate green.
- `ocm -t examples/ocm.conf` exits 0; a bad file reports every problem.
- A stranger can go from a share URL to serving a model with one command.
- An agent key cannot exceed its allowlist, rate or budget.
- A reload never drops an active stream and never applies an invalid file.
- `docs/ROADMAP.md` Phase 1.5 outcomes are flipped from planned to measured.
